Respectful Home Visits

Practise a few decisions that help keep home visits respectful, consent-aware and within role. This sample uses standard controls that work with a keyboard, touch or pointer; it does not rely on dragging.

Before you begin

How to use this practice

Choose one response for each situation, then select Check response. Feedback explains the reasoning. You can change an answer and check it again.

  • Use Tab and Shift + Tab to move through the page.
  • Within a set of radio options, use the arrow keys to change your selection.
  • No response is timed, and your answers are not saved or sent anywhere.

Design notes

Accessibility decisions in this sample

This prototype is designed against selected WCAG 2.2 AA criteria. The notes below describe what is implemented and what still needs manual verification; they are not a claim that the whole page conforms.

2.1.1 Keyboard · 2.4.7 Focus Visible

Use native controls and a visible focus style

Each decision uses a labelled radio group and a submit button. A strong outline appears as keyboard focus moves through the page.

Verify: complete every decision using keyboard alone and confirm focus remains visible.

2.4.11 Focus Not Obscured · 2.5.8 Target Size (Minimum)

Keep controls visible and comfortably sized

The page has no sticky overlays, and answer rows and buttons have generous hit areas.

Verify: check focus at narrow widths and measure target size/spacing against the criterion.

1.4.3 Contrast (Minimum) · 1.4.10 Reflow

Keep text readable as the viewport changes

The sample uses a single-column layout that can narrow with the viewport and browser zoom. Text and controls do not depend on colour alone.

Verify: measure text and control contrast, then review at 320 CSS pixels and 200% zoom.

1.3.1 Info and Relationships · 3.3.2 Labels or Instructions

Make structure and instructions available to assistive technology

Headings organise the page; each question uses a fieldset, legend and explicitly labelled native options. Instructions explain how to use the interaction.

Verify: review the accessibility tree and listen through the page with a screen reader.

2.5.7 Dragging Movements · 4.1.3 Status Messages

Offer a simple response path and useful feedback

The scenario does not require dragging. Feedback is written in text, identifies the reasoning, and is announced through a status message.

Verify: test that each feedback message is announced with a screen reader. Dragging Movements is not applicable to this interaction because no dragging is required.

Conformance scope WCAG conformance applies to complete pages and all applicable Level A and AA criteria, not to a feature label or authoring tool. Before making a conformance claim, check contrast, reflow, keyboard operation, screen-reader output, all feedback states, and any hosted or embedded content.

Reference: W3C WCAG 2.2 Quick Reference.
